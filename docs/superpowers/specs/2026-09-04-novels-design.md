# Novels in the same app (1d)

**Date:** 2026-09-04
**Status:** Design — build-through, but **dark in production** until the owner flips it live.
**Branch:** `feat/vps-slim-source-native` (same branch; no parallel infra).

## 1. What the owner asked for (2026-09-04, verbatim intent)

1. A **novel reader in the same app** — build now.
2. **Novel source connectors** — "archive"-type sites where all the novels live.
3. **TTS audiobooks later**, generated by a model on the owner's RTX 3090 Ti — explicitly
   *not now*; nothing here builds it, but the text pipeline must leave it cheap.
4. **Production stays a manhwa site** meanwhile: nothing novel-shaped may appear on the
   live web or app until the owner says so. Manhwa work continues in parallel.

## 2. Gating — how "build it but don't ship it" works

- `MM_NOVELS_ENABLED` (settings, env-overridable), **default false**. The prod compose does
  not set it.
- Backend: novel connectors register only when the flag is on; novel routes 404 when off
  (404, not 403 — an off feature should be indistinguishable from an absent one).
- Clients: the pre-auth/config surface the clients already read gains
  `novels_enabled: bool`. Web and mobile mount novel UI **only when the server says so** —
  the binaries ship with the code dormant, which is unavoidable since builds are automatic.
- Flipping one env var on the VPS turns the whole feature on later. Tests exercise the
  flag both ways.

## 3. Data model — novels are sources, not a new system

The source-native identity carries over unchanged: a novel is `(source_id, series_key)`,
a chapter `(source_id, series_key, chapter_key)`, `chapter_number` float alongside.
Follows, library, progress (furthest-wins), notifications, collections, statistics: all
reuse the existing rows and services untouched.

New/changed:

- `content_kind: "manga" | "novel"` on the connector class and the sources listing —
  clients branch on it to open the right reader. Existing connectors are implicitly
  `"manga"`; no migration needed for them.
- **Chapter text endpoint** (novel analog of the reader manifest):
  `GET /novels/chapter?source=&series=&chapter=` →
  `{title, chapter_number, paragraphs: [str], prev, next, word_count}`.
  Paragraphs are **sanitized plain text** (scripts/styles/ads stripped, aggregator
  watermark lines removed) — canonical storage form, chosen deliberately so TTS later
  reads it directly. No HTML passthrough to clients.
- **Cache:** `novel_chapter_cache` keyed `(source_id, series_key, chapter_key)`, TTL long
  (text is small and immutable in practice), stale-on-failure like the browse cache.
  Chapter text is small enough to store server-side WITHOUT violating the no-chapter-bytes
  rule — that rule exists for multi-GB image libraries; a full novel is a few MB of text.
  Budget guard anyway: cap the cache table (LRU sweep) so it cannot grow unbounded.
- Browse/search/detail reuse the existing `/sources/*` shapes (a novel series listing is a
  series listing).

## 4. Connectors

- Same connector interface, `content_kind = "novel"`, plus `chapter_text(series_key,
  chapter_key) -> NovelChapterText`.
- First wave: probe **from the VPS** (the OVH egress is Cloudflare-challenged where
  residential IPs are not; local probes lie) across Royal Road + the big aggregator
  archives (FreeWebNovel, NovelBin class), ship the two that work best. The owner may name
  specific sites; swap accordingly.
- Fixture-recorded tests per connector, like the manga ones.

## 5. Readers

- **Mobile:** a text reader screen — font size / line height / theme (reuse the reader's
  overlay+prefs patterns, per-series), scroll-position progress mapped onto the existing
  `last_page`/`page_count` fields as paragraph-bucket indices so furthest-wins merge works
  unchanged. Offline: downloaded chapters store their paragraph text as a blob in the
  existing content-addressed store (text bytes are just small blobs; refcounting and
  read-then-expire apply as-is).
- **Web:** same endpoint, a comfortable column-width text view with the same progress
  mapping. Parity, per the standing rule.
- Both hidden behind the server flag (§2).

## 6. TTS (recorded so it is not re-litigated; NOT in scope)

Later: a service on the owner's 3090 Ti machine turns chapter paragraphs into audio; the
app plays/downloads it. Everything it needs from this slice is already guaranteed by §3:
clean paragraph text per chapter, addressable by the identity triple. Nothing else is
built now.

## 7. Slices

| Slice | Scope |
|---|---|
| N1 backend | flag + `content_kind` + chapter-text endpoint + cache + 2 connectors, tests both flag states |
| N2 web reader | flag-gated novel browse/detail/reader + progress mapping |
| N3 mobile reader | flag-gated reader + offline text downloads + progress outbox reuse |
| N4 (last, gated on owner) | TTS pipeline — separate spec when the time comes |

### N1 as built (2026-09-04, commits `f998b23` foundation + `cf1de13` connector)

Shipped per §2–§4 with two mid-flight owner redirects folded in: **English
only** (connectors declare `LANGUAGE = "en"`, and a conservative English
guard fails any non-English chapter before it can be cached), and the
connector list narrowed to **one flagship: novelarchive.cc** (owner's call —
a ~61k-title English archive with a real JSON API; listing/detail/chapter
endpoints discovered and fixture-captured from the VPS). A fleet builds the
other connectors on this foundation; VPS probe record for them: Royal Road
200 clean, FreeWebNovel 200 clean, NovelFull 200 clean (incl. the one-shot
`/ajax-chapter-option` full chapter list), NovelBin NXDOMAIN,
LightNovelWorld/LightNovelPub/NovelHall/ranobes.top Cloudflare-challenged
even via curl_cffi impersonation.

Deltas from the letter of §3, all additive: the `/novels/chapter` payload
also carries the identity triple and the standard `cache` block
(fresh/live/stale like the browse endpoints); the sources listing gained
`language` alongside `content_kind` (novel sources say `"en"`, legacy manga
connectors say `null`); the cache table's LRU is a real least-recently-USED
sweep (`last_used_at` bumped on read) rather than the browse cache's
oldest-fetched sweep, because immutable chapter text a reader returns to is
exactly what is worth keeping; `novels_enabled` rides on
`GET /auth/bootstrap-status` (the clients' existing pre-auth config read).
Flag-off is enforced one level deeper than routes: novel connector classes
stay registered but every registry query surface (listing, instantiation,
type enumeration) hides them, so `/sources/*` 404s them exactly like sources
that were never built, and the `/novels` router simply is not mounted.
